# LR3 答辩速查

## 展示顺序

1. 打开俄语报告封面，再翻到开发集检索对比。Hit@3 看有没有找中，Recall@3 看找全多少，MRR@3 更看重第一个证据的排名。
2. 打开 selection.json。说明先在 dev 比较 MRR@3，再看 Recall@3，最后按 BM25 → RRF → RRF + CE 的简单程度打破平局。打开 Git 历史，确认选型提交先于 holdout。
3. 双击 01_mlflow.bat，在 MLflow 比较 SciFact dev 与 SciFact holdout。报告中的逐例证据在 reports/traces.json，原始 JSONL 在 runs/。
4. 运行 python analyze.py。默认从保存的结果重算，不调用语言模型。

## 老师可能追问

- BM25 的精确词项匹配能利用缩写和标志物。Dense 通过向量相似度捕获改写。互补表给出只有一种方法命中的数量。
- 如果文档在 Dense 排第 2，BM25 未返回，RRF 的贡献为 1/62 + 0。错误把它当成 BM25 第 21 会额外加 1/81，改变排序。
- CE 对每条查询只重新排序原来的 20 篇文章。Recall@20 保持不变，前三篇和证据句是否进入 2048 token 上下文仍可能变化。
- 检索变好但答案没变时，检查候选排名、实际传入证据句、模型标签和引用。标签、引用、证据覆盖用的是不同指标。
- 90 条 dev 和 210 条 holdout 的 CE 分别评估 1,800 和 4,200 个文档对。报告的耗时以每条查询计，含分词和模型评分，排除预热。
- 把 RRF 常数从 60 改为 1，会更重视靠前的单份列表。可以用保存的前 20 名计算这个变化，无需重跑模型。正式 holdout 结果仍对应已冻结的常数 60。
