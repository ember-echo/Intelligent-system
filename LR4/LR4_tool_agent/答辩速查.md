# LR4 答辩速查

正式结果来自 runs/holdout/results.jsonl。reports/summary.json 是可重算的汇总，reports/traces.json 保存正文案例的实际消息、参数、工具结果和校验结果。演示时可以先打开报告，再用 python analyze.py 重算，最后在 MLflow 查看正式运行。

1. **参数错误怎么看？** 从工具 trace 找 error，再看下一条模型请求里的工具结果。判断它是否提交了更正后的参数，以及原来的动作是否生效。
2. **什么时候 ReAct 可能占优？** 如果读完结果才知道下一步应该用哪一个工具，ReAct 可以改变路线。固定计划适合工具顺序已知、仅参数取决于中间观察的任务。
3. **为什么输入 token 增长较快？** ReAct 每轮重新提交完整工具说明和不断增长的历史。统计用每次调用返回的 prompt_tokens 相加。缓存可加速计算，但不会让逻辑上的输入 token 消失。
4. **为什么把工具结果堆成答案也能通过 36/40？** 部分 utility 会检查是否出现目标文本或状态是否正确。离线参考回放用于验证适配器，正式评估仍看回复是否准确、简洁及是否完成指定操作。
5. **固定计划能约束什么？** 工具名称和顺序在读观察结果前确定，框架逐步限制可用工具。参数和最终回复仍由模型根据观察产生，因此还需验证参数、观察来源和副作用。
6. **工具上限从 15 改为 3 会怎样？** 参考工具调用超过三次的任务风险最高。较短任务也可能因为查找错误或重复调用提前耗尽额度。验证时应使用开发集和独立配置。
7. **为什么必须有最终文字？** AgentDojo 通过最终助手消息取出答案并评分。保留文字结果和明确停止原因，可以避免框架因缺少回复而重试，破坏每题每模式只跑一次的协议。
